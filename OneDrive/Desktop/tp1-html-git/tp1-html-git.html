TP 1 : HTML5, Git/GitHub & Inspection Web

Enseignant : Bouraoui Moutii & Malek Khadhrani Module : Atelier Développement Web 1 Niveau : 1ère année Licence TI Durée : 3 h

🎯 Objectifs Généraux du Travail Pratique

À la fin de ce TP, l'étudiant sera capable de :

  • Concevoir une structure HTML5 sémantique et valide.
  • Suivre son code source avec Git et le déployer sur GitHub.
  • Inspecter le comportement d'une page web via les Outils de Développement (DevTools) du navigateur.

Phase 1 : Environnement & Workflow Git / GitHub

Étape 1.1 : Préparation de l'environnement

1. Téléchargez et installez VS Code si ce n'est pas déjà fait.

2. Ouvrez VS Code et installez les extensions suivantes via l'onglet Extensions (Ctrl+Shift+X) :

  • Live Server (ou Live Preview) : Permet de voir les modifications en direct.
  • Prettier - Code Formatter : Maintient un code propre et bien aligné.

3. Créez un dossier nommé tp1-html-git sur votre machine et ouvrez-le dans VS Code.

Étape 1.2 : Configuration & Initialisation Git

Ouvrez le terminal intégré de VS Code (Ctrl + `) et exécutez les commandes suivantes :

# Configuration globale de votre identité (à faire une seule fois)
git config --global user.name "Votre Nom"
git config --global user.email "votre.email@exemple.com"

# Se placer dans le dossier et initialiser le dépôt
cd tp1-html-git
git init
git branch -M main

# Liaison avec votre dépôt distant sur GitHub
# (Créez d'abord un dépôt public nommé "tp1-html-git" sur github.com sans fichier README)
git remote add origin https://github.com/votre-user/tp1-html-git.git

💡 Explications Pédagogiques (Phase 1)

  • Live Server / Live Preview : Lance un serveur web local. À chaque sauvegarde (Ctrl+S), il rafraîchit automatiquement la page dans le navigateur.
  • Prettier : Automatise l'indentation du code. Il garantit un code propre en alignant correctement les balises HTML.
  • git init : Crée un dossier caché .git qui sert de base de données pour enregistrer tout l'historique des modifications.
  • git branch -M main : Renomme la branche par défaut en main (norme standard actuelle sur Git/GitHub).
  • git remote add origin : Établit le pont de connexion entre le projet local sur l'ordinateur et le serveur GitHub en ligne.

Étape 1.3 : Le cycle des Commits & Push

Créez le fichier index.html dans votre dossier, ajoutez la structure minimale HTML, puis enregistrez votre travail avec les commandes suivantes :

git status                               # Vérifie les fichiers modifiés / non suivis
git add index.html                       # Ajoute le fichier à la zone de transit (Staging Area)
git commit -m "feat: initialisation de la structure HTML5"
git push -u origin main                  # Envoie les modifications vers le dépôt distant GitHub

💡 Le cycle de vie Git

Le flux Git se décompose toujours en 3 zones distinctes :

  • Working Directory (Espace de travail) : Vos fichiers réels modifiés sur le disque dur.
  • Staging Area (Index) : La zone de préparation créée via git add. Vous y choisissez exactement ce qui fera partie du prochain enregistrement.
  • Repository (Dépôt local/distant) : L'historique permanent validé via git commit et synchronisé avec git push.

Phase 2 : Analyse Client/Serveur & DevTools Chrome

1. Onglet Network (Réseau)

Ouvrez votre page via Live Server, puis ouvrez les Outils de Développement en appuyant sur F12.

  • Allez dans l'onglet Network (Réseau) et rafraîchissez la page (F5).
  • Code Status 200 OK : Indique le succès de la requête HTTP.
  • Type Content-Type : Indique que le serveur envoie du texte au format HTML (text/html).

2. Onglet Console

Ouvrez l'onglet Console dans les DevTools et saisissez l'instruction JavaScript suivante :

document.body.style.backgroundColor = "#f0f8ff";

💡 Explications Pédagogiques (Communication Web & DOM)

  • Architecture Client/Serveur : Le navigateur (client) envoie une requête HTTP. Le serveur web répond en envoyant le fichier HTML accompagné de headers (statut 200 OK, type MIME text/html).
  • Manipulation du DOM : L'instruction exécutée en console montre que la structure HTML est transformée par le navigateur en un arbre d'objets (Document Object Model) modifiable dynamiquement en mémoire.

Phase 3 & 4 : Structuration HTML5 & Validation

Vous devez concevoir la page web d'une conférence informatique contenant :

  • Un en-tête sémantique (<header>) avec titre et menu de navigation.
  • Une section Programme contenant un tableau HTML (<table>).
  • Une section Inscription avec un formulaire sémantique (<form>, champs input, select, button).
  • Un pied de page (<footer>) avec le copyright.
